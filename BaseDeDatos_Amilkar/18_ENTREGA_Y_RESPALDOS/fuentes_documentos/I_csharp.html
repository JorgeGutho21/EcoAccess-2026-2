Hay dos bases de datos distintas y no se deben confundir:

Cómo se conectan funcionalmente: el modelo académico es el mismo sistema EcoAccess explicado y normalizado para la materia. Comparten 16 tablas (por ejemplo USUARIO, CONTENEDOR, DEPOSITO y MOVIMIENTO_ECOPUNTOS); la comparación completa está en 14_INTEGRACION_PROGRAMACION_III/MATRIZ_P3_vs_ACADEMICO.md.

Los datos no se copian de una base a la otra. Si se quisiera ver P3 en Power BI, se haría con una cuenta lectora sobre las vistas de P3. Esa cuenta solo está propuesta (14_INTEGRACION_PROGRAMACION_III/PROPUESTA_lector_bi_p3_NO_EJECUTADO.sql) y necesita autorización, porque no se modifica la base de producción.

La idea en una frase

Un programa en C# no «tiene» la base de datos: le envía órdenes SQL a Oracle por la red (aunque sea el mismo PC) y recibe filas o mensajes de error. Para hablar con Oracle, C# necesita un «traductor»: la biblioteca ODP.NET administrado (paquete NuGet Oracle.ManagedDataAccess.Core). «Administrado» significa que está escrita en .NET y no hace falta instalar Oracle Client.

Esta aplicación académica es distinta de EcoAccess P3 (la aplicación Windows Forms con Telegram, QR y prototipo ESP32). P3 no se modificó. Aquí solo hay dos programas pequeños para demostrar la conexión a la base académica.

La conexión segura: sin contraseñas en el código

Una cadena de conexión es el texto que le dice a ODP.NET a dónde ir y con quién entrar: servidor, usuario y contraseña. Si se escribiera en el código, cualquiera que viera el repositorio la conocería. Por eso Conexion.Crear la arma con variables de entorno del PC:

Las piezas de ODP.NET explicadas

Clase / propiedadQué esAnalogía
OracleConnectionLa conexión abierta con Oracle. Se abre con Open() y se cierra sola al salir del using.La llamada telefónica.
OracleCommandUna orden: una sentencia SQL o el nombre de un procedimiento.Lo que dices en la llamada.
CommandType.StoredProcedureIndica que la orden es el nombre de un procedimiento PL/SQL (pkg_empleado_crud.insertar).«Pásame con el departamento X».
BindByName = trueLos parámetros se asocian por nombre (p_nombre), no por posición. Por defecto ODP.NET los asocia por orden, y un orden equivocado mete el salario en el nombre sin dar error.Etiquetar los sobres.
Parameters.Add(...)Envía valores separados del texto SQL. Así no hay inyección SQL.Rellenar un formulario en vez de dictar una frase.
ParameterDirection.OutputUn valor que Oracle devuelve (el id generado por la secuencia).El número de turno.
OracleDbType.RefCursorRecibe un SYS_REFCURSOR: un puntero a filas que C# lee con un OracleDataAdapter.Un enlace a una lista.
ExecuteNonQuery()Ejecuta algo que no devuelve filas (INSERT, UPDATE, procedimiento).—
ExecuteReader() / Fill()Ejecuta un SELECT y recorre o carga las filas.—
BeginTransaction(), Commit(), Rollback()Agrupa operaciones: o se confirman todas o ninguna.Firmar el contrato o romperlo.
OracleException.NumberEl número ORA del error (20002, 942…).El código del problema.

El repositorio del CRUD sin DELETE

{{FILE:10_CSHARP_VISUAL_STUDIO/SOLUCION_CSHARP/EcoAccessBD.Datos/RepositorioEmpleados.cs}}

Por qué cada escritura tiene su transacción: si el INSERT falla a mitad, using descarta la transacción sin confirmar y no queda nada a medias. La propiedad SoloPrueba hace ROLLBACK en vez de COMMIT para que la prueba automática no deje datos.

Por qué no hay Eliminar(): lo pide la práctica. Un empleado no se borra; se corrige con UPDATE. Así se conserva la historia.

La ventana: qué hace cada botón

BotónLlama aQué pasa en Oracle
Consultarpkg_empleado_crud.consultar(p_depto)Función que devuelve SYS_REFCURSOR con los empleados del departamento.
Insertarpkg_empleado_crud.insertar(...)La secuencia asigna el id; COMMIT. La tabla se recarga y queda seleccionada la fila recién insertada.
Actualizarpkg_empleado_crud.actualizar(...)UPDATE por id; si no existe, el paquete lanza ORA-20002 y la ventana lo muestra en rojo.

Defecto corregido: antes, al recargar la tabla después de insertar, el evento SelectionChanged cambiaba el Id del formulario por el de la primera fila, y «Actualizar» modificaba a otro empleado. Ahora la bandera _cargando ignora ese evento durante la recarga y Recargar(id) vuelve a seleccionar el empleado correcto. La captura 3 lo demuestra: el empleado actualizado es el mismo id que se insertó.
