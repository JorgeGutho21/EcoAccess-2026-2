# 11 · Secuencias y claves primarias

## 1. Qué significa

- **Clave primaria (PK)**: la columna o columnas que identifican **una sola fila**. No se repite ni es NULL.
- **Secuencia**: un objeto de Oracle que entrega números 1, 2, 3… sin repetir, aunque muchas sesiones pidan a la vez.
- **IDENTITY**: una columna que usa una secuencia interna automáticamente (Oracle 12c y posteriores).

## 2. Para qué sirve, 3. por qué y 4. cuándo se usa

La PK permite que las FK apunten a una fila exacta. EcoAccess usa claves **subrogadas**: un número sin significado de negocio. Así, si cambia el nombre de una estación, no se rompen las referencias. Se usa en toda tabla que otras referencian.

## 5. Estructura

```sql
-- Forma moderna (la que usa EcoAccess):
id_deposito NUMBER(10) GENERATED ALWAYS AS IDENTITY,
CONSTRAINT pk_deposito PRIMARY KEY (id_deposito)

-- Forma clásica (la de la tarea del profesor, punto 2):
CREATE SEQUENCE seq_x START WITH 1 INCREMENT BY 1;
-- + un trigger BEFORE INSERT que hace :NEW.id := seq_x.NEXTVAL;
```

| Opción | Qué permite |
|---|---|
| `GENERATED ALWAYS AS IDENTITY` | Nadie puede escribir el id; un INSERT con id da ORA-32795. Se usa en las tablas de operación: depósitos, movimientos y auditoría. |
| `GENERATED BY DEFAULT ON NULL AS IDENTITY` | Si el INSERT no trae id (o trae NULL), se genera; si lo trae, se respeta. Se usa en los catálogos (MATERIAL, ROL, CONTENEDOR, PUNTO_INSTALACION, PESO_REFERENCIAL), que se cargan con ids fijos. |

## 11. Errores frecuentes

| Error | Causa |
|---|---|
| ORA-00001 restricción única violada | Se insertó una PK repetida, por ejemplo al escribir a mano un id de catálogo que ya existe. |
| ORA-32795 no se puede insertar en una columna GENERATED ALWAYS | Se envió un valor al id de una tabla `ALWAYS`. Quita la columna del INSERT. |
| ORA-01400 no se puede insertar NULL | Falta la PK en una tabla sin IDENTITY. |
| ORA-08002 CURRVAL no definido en esta sesión | Se pidió `CURRVAL` sin haber pedido antes `NEXTVAL` en la sesión. |

## 12. Preguntas del profesor

- ¿Por qué hay huecos en los id? *Un ROLLBACK no devuelve el número ya entregado, y la caché de la secuencia se pierde si la base se reinicia.*
- ¿IDENTITY o secuencia + trigger? *IDENTITY hace lo mismo con menos código. La tarea pide la forma clásica para entender `NEXTVAL` y `:NEW`.*
- ¿Por qué no usar la cédula como PK? *Es dato personal, puede cambiar o faltar, y EcoAccess minimiza datos personales.*
