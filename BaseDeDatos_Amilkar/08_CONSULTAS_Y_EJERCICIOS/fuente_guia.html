Cómo usar esta guía

Esta guía está escrita para alguien que nunca ha usado una base de datos. Si tienes 14 años y sabes usar un computador, la puedes seguir. Cada capítulo explica una idea con palabras sencillas y luego la practica con ejercicios reales.

La regla de oro: escribe y ejecuta cada ejercicio tú mismo. Leer SQL sin ejecutarlo es como aprender a nadar leyendo.

  • Los capítulos 1 a 9 enseñan las herramientas: qué es cada cosa, cómo conectarse y qué hacer cuando sale un error.
  • Los capítulos 10 a 14 explican el proyecto EcoAccess y los conceptos de PL/SQL y disparadores.
  • El capítulo 15 es el banco de 309 ejercicios. Todos se ejecutaron de verdad en Oracle, y debajo de cada uno aparece el resultado que se obtuvo.

Sobre los datos: todos los nombres, correos y depósitos de EcoAccess BD son SINTÉTICOS (inventados). «María Gómez Oñate» no es una persona real. Los correos terminan en @ejemplo.test, un dominio que no existe.

Sobre las capturas: esta guía no trae capturas de pantalla, porque durante su elaboración no se pudo controlar la ventana de SQL Developer. En su lugar, cada paso dice exactamente qué menú y qué botón usar, y los resultados se copiaron tal cual de la ejecución real.

Palabras que vas a oír mucho

  • Tabla: una hoja de cálculo con columnas fijas. Ejemplo: MATERIAL.
  • Fila: un registro de la tabla. Ejemplo: el material «PET».
  • Columna: un dato de cada fila. Ejemplo: categoria.
  • Esquema (usuario): la carpeta de un dueño, donde están sus tablas. Aquí se usan ECOACCESS_BD, ECOACCESS_PRACTICAS y HR.
  • Clave primaria (PK): el número de cédula de cada fila; no se repite.
  • Clave foránea (FK): una columna que apunta a la PK de otra tabla. Por ejemplo, cada caneca apunta a su estación.
  • SQL: el idioma para pedir datos (SELECT) o cambiarlos (INSERT, UPDATE, DELETE).
  • PL/SQL: SQL con superpoderes de programación: variables, IF, ciclos, procedimientos y disparadores.
  • Transacción: un grupo de cambios que se confirma junto (COMMIT) o se deshace junto (ROLLBACK).

Crear la conexión al esquema EcoAccess BD

  1. Abre SQL Developer. A la izquierda verás el panel Conexiones.
  2. Haz clic en el + verde (Nueva conexión).
  3. Llena los campos:

    • Usuario: ECOACCESS_BD
    • Contraseña: la que el equipo definió al instalar. Nunca la escribas en un documento.

Repite los mismos pasos para ECOACCESS_PRACTICAS (ejercicios de clase) y, si lo necesitas, para HR. La conexión system solo se usa para instalar (crear usuarios); no hagas ejercicios con ella.

PL/SQL explicado sin miedo

Un bloque anónimo, línea por línea

SET SERVEROUTPUT ON                                  -- (1) mostrar mensajes
DECLARE                                              -- (2) aquí se declaran variables
    v_total NUMBER;                                  -- (3) una variable numérica
    v_nombre material.nombre%TYPE;                   -- (4) mismo tipo que la columna
BEGIN                                                -- (5) empieza la acción
    SELECT COUNT(*) INTO v_total FROM material;      -- (6) el resultado va a la variable
    IF v_total > 20 THEN                             -- (7) decisión
        DBMS_OUTPUT.PUT_LINE('Catálogo grande: ' || v_total);
    ELSE
        DBMS_OUTPUT.PUT_LINE('Catálogo pequeño');
    END IF;
EXCEPTION                                            -- (8) qué hacer si algo falla
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM);
END;                                                 -- (9) fin del bloque
/                                                    -- (10) la barra ejecuta el bloque
  • (4) %TYPE copia el tipo de la columna: si mañana la columna crece, la variable crece con ella.
  • (6) SELECT … INTO debe devolver exactamente una fila. Si no devuelve ninguna, salta NO_DATA_FOUND; si devuelve varias, TOO_MANY_ROWS.
  • (10) La barra / en una línea sola le dice a SQL Developer o a SQL*Plus «ejecuta el bloque». Sin ella, no pasa nada.

De bloque a procedimiento y a función

Bloque anónimoProcedimientoFunción

¿Devuelve un valor?NoPor parámetros OUTSí, con RETURN (puede ser un SYS_REFCURSOR)
¿Se usa en un SELECT?NoNoSí, si no modifica datos

Cursores

  • Implícito: Oracle lo crea solo en cada SELECT INTO, INSERT o UPDATE. SQL%ROWCOUNT dice cuántas filas tocó.
  • Explícito: se declara con CURSOR c IS SELECT … y se recorre con OPEN, FETCH y CLOSE, o más fácil con FOR fila IN c LOOP.
  • SYS_REFCURSOR: un cursor que se puede devolver a otro programa, por ejemplo a C#. Lo usan PKG_ESTADISTICAS.ranking_verificados y pkg_empleado_crud.consultar.

Paquetes

Un paquete es una caja con varias funciones y procedimientos relacionados. Tiene dos partes: la especificación (lo que se puede usar desde afuera) y el cuerpo (cómo funciona por dentro).

PKG_ECOPUNTOS agrupa todo lo de puntos. Además puede tener variables privadas: en PKG_DEPOSITO, g_correccion solo se activa durante una corrección autorizada.

Disparadores: :OLD, :NEW, BEFORE y AFTER

Un disparador (trigger) es un programa que Oracle ejecuta solo cuando pasa algo en una tabla. Es como una alarma que suena cuando abren una puerta.

La tabla que hay que memorizar

Operación:OLD:NEW
INSERTTodo NULL (la fila no existía)La fila nueva
UPDATELa fila antes del cambioLa fila después del cambio
DELETELa fila que se borraTodo NULL
  • :OLD nunca se puede cambiar.
  • :NEW se puede cambiar solo en un BEFORE … FOR EACH ROW. En AFTER ya es tarde: la fila está guardada.
  • En la cláusula WHEN se escribe NEW.estado sin dos puntos; dentro del cuerpo, :NEW.estado con dos puntos.
  • Un trigger no hace COMMIT. Si la operación se deshace, lo que hizo el trigger también.
