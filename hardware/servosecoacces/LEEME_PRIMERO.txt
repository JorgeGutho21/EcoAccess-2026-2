ECOACCESS P3 — UNA CANECA, DOS SERVOS, UNA TAPA

1. QUÉ NECESITAS
ESP32-WROOM, cable USB de datos, dos servomotores SG90, cables y fuente externa apropiada.
No se ha confirmado un sensor de ingreso. Este firmware no inventa uno.
El programa original está guardado, sin cambios, en:
../arduino/referencia/servosecoacces/servosecoacces.ino
Ese original mueve los servos continuamente: no es el que debes usar para integrar EcoAccess.

2. CABLES Y ALIMENTACIÓN
Señal servo 1: GPIO 18. Señal servo 2: GPIO 19, según el código entregado.
Ambos motores mueven LA MISMA TAPA, no dos canecas.
Alimenta los servos con una fuente externa adecuada a su modelo y comparte GND con el ESP32.
No alimentes los servos desde 3,3 V del ESP32. Verifica el color/función de cada cable en el modelo real.
La fuente actual de 5 V/1 A NO se ha validado para dos motores bajo carga: mide arranque y bloqueo antes de montarlos.
Prueba primero sin carga ni unión a la tapa. Los ángulos 0 y 90 del original no prueban posiciones seguras.
Confirma sentido de giro, topes y que los servos no se opongan entre sí.

3. ARDUINO IDE Y LIBRERÍAS
Abre ESTA carpeta servosecoacces y su archivo servosecoacces.ino.
Selecciona el modelo exacto de placa ESP32-WROOM; si corresponde, ESP32 Dev Module.
Selecciona el puerto COM que aparece al conectar por USB. No elijas un puerto por adivinación.
Usa el paquete esp32 de Espressif 3.x (se verificó sintaxis con el 3.3.12 instalado).
LEDC, Preferences, cJSON y Mbed TLS vienen con ese paquete: no hace falta descargar una biblioteca de servo adicional.
Estado comprobado aquí: compilador Xtensa ESP32 y cabeceras reales aceptaron el código mediante -fsyntax-only.
El 1/11 se compiló y enlazó el firmware completo con Arduino CLI 1.5.2-rc.1 y core 3.3.12, perfil esp32:esp32:esp32. No se cargó una placa ni se probó gráficamente Arduino IDE. Ver docs/modulos/57_FIRMWARE_ENLAZADO.md.

4. CONFIGURACIÓN PRIVADA
Copia configuracion_ejemplo.h como configuracion_privada.h en esta misma carpeta.
Ese archivo está excluido de Git. No compartas ni subas la clave.
Escribe la identidad, identificador de caneca, versión y clave HMAC Base64 del archivo privado del bridge.
NO uses un token de Telegram ni contraseña Oracle. El ESP32 no necesita esos datos.
Verifica los ángulos abierto/cerrado de CADA motor y la alimentación antes de poner CALIBRACION_VERIFICADA=true.
Sin configuración o calibración, el programa NO mueve motores y no fija un binding inválido en memoria.

El transporte de esta entrega es USB: no necesitas escribir contraseña WiFi, dirección IP ni abrir puertos de red.
El ESP32 debe permanecer conectado por USB al computador del bridge.
Una futura conexión inalámbrica requiere otro transporte protegido; no publiques el bridge actual en Internet.

5. COPIAR, COMPILAR Y CARGAR
Conserva juntos .ino y sus cabeceras en la carpeta servosecoacces.
Pulsa Verificar en Arduino IDE. Si compila, pulsa Subir con la placa y COM correctos.
No borres la memoria NVS para resolver un error: contiene reservas contra repeticiones.
El firmware no mueve los motores al encender o reiniciar. Esto es intencional.
No conectes una tapa cargada para el primer ensayo.

6. CONECTAR CON ECOACCESS
En el computador del bridge deben estar Oracle y la configuración privada del bridge ya preparados.
Conserva el mismo dispositivo, caneca, clave y versión en firmware y bridge.
Añade Bridge:PuertoSerial con tu COM real al archivo JSON PRIVADO del bridge (fuera de Git).
Compila la solución C# y arranca el bridge existente con --bridge y el adaptador con --dispositivo-serial.
El adaptador USB lee solo configuración Bridge, no secretos Oracle ni Telegram.
Si usas una ruta privada distinta, selecciona ECOACCESS_ARCHIVO_BRIDGE antes de iniciar los procesos.
No arranques --dispositivo-simulado junto con --dispositivo-serial: comparten exclusión/diario para evitar doble ejecución.
El lanzador general todavía no selecciona automáticamente este modo; no está declarado como arranque de un clic.

7. PRUEBA DE APERTURA Y CIERRE
Con montaje calibrado y sin carga, registra una orden ficticia admitida por EcoAccess.
El gateway comprueba su autorización actual. El ESP32 envía un desafío nuevo y acepta solo un permiso HMAC vigente.
Reserva orden y nonce en memoria persistente ANTES de mover ambos motores.
Solicita posición abierta de ambos, espera el tiempo configurado y solicita cerrado de ambos.
Una repetición no debe moverlos de nuevo. Una orden vencida o revocada tampoco.
La respuesta autenticada solo confirma que se solicitaron señales PWM: observa físicamente la tapa.
Sin sensores no se informa apertura/cierre físico ni ingreso detectado.
El gateway registra acuse y fallo por falta de confirmación física; NO crea un depósito ni ecopuntos automáticamente.
Para completar posteriormente depósitos físicos se necesitan sensores y evidencia real, conservando el protocolo.

8. REINICIO, DESCONEXIÓN O ERRORES
Si se corta la energía durante una operación, no vuelve a abrir al arrancar: queda bloqueado para revisión.
Comprueba físicamente que la tapa y motores estén seguros. Solo el responsable puede marcar
RECUPERACION_MANUAL_VERIFICADA=true, cargar una vez y volver a false después de recuperar.
Esto no borra las reservas ni permite repetir una orden antigua. No lo dejes activado permanentemente.
No borres el diario del gateway, cambies su binding ni borres NVS para forzar otra apertura.
Si la memoria de reservas se llena, el firmware rechaza nuevas órdenes: pide mantenimiento seguro, sin borrar a ciegas.
Si COM está ocupado, cierra el monitor serie de Arduino antes de iniciar el adaptador.
Si falla la firma o binding, revisa identidad/caneca/versión/clave localmente, sin mostrarlas en chats o capturas.
Si no hay recibo a tiempo, consulta el estado y revisa el montaje: no repitas automáticamente una actuación incierta.
Un error de PWM o de escritura flash bloquea el actuador; no prueba que haya abierto o cerrado.

9. ESTADO REAL
Código integrado en el mismo Bot/bridge, transporte USB y controles preparados.
Firmware completo compilado y enlazado; prueba física, calibración eléctrica/mecánica y carga: PENDIENTES.
Nunca presentar un movimiento solicitado como depósito detectado, material verificado o ecopuntos.
