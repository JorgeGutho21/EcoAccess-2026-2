## 3. Normalización

* **1FN**: valores atómicos; las listas (roles de un usuario, materiales de una caneca) van en tablas puente (`USUARIO_ROL`, `CONTENEDOR_MATERIAL`).
* **2FN**: las tablas puente solo tienen la clave compuesta y metadatos de esa relación.
* **3FN**: no hay dependencias transitivas guardadas: el **color** de una caneca no se almacena porque depende de la categoría (`CONFIGURACION_CANECA.categoria`); el nombre del material no se copia en `DEPOSITO`, se referencia por `id_material`.
* Desnormalización consciente: ninguna en tablas; las vistas de informes agregan para lectura.

## 4. Tipos de datos y convenciones

`VARCHAR2(n CHAR)` (longitud en caracteres, AL32UTF8), `NUMBER(1)` con CHECK (0,1) para verdadero/falso, `TIMESTAMP` en UTC, enumeraciones como `NUMBER` con los mismos valores del `enum` de C#, identidades `GENERATED BY DEFAULT ON NULL AS IDENTITY`.

## 5. Transacciones y concurrencia

* Los repositorios abren una transacción para operaciones de varias filas (por ejemplo vincular Telegram o acreditar ecopuntos) y bloquean filas con `SELECT … FOR UPDATE` donde hay riesgo de doble acreditación.
* `CONVERSACION_TELEGRAM.version` aplica concurrencia optimista: dos mensajes simultáneos de la misma persona no se pisan.
* Evidencia: 10 sesiones simultáneas correctas en 1,2 s y prueba de `ROLLBACK` (ver `docs/integracion/CONEXION_CSHARP_ORACLE_CLOUD.md`).
